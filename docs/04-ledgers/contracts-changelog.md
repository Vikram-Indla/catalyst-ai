# Contracts changelog

Every change to anything the backend relies on (`RULE-003`): an operation, a request or response
shape, an error code, a header, a stream frame, a job status, a configuration variable, a port
method. Newest first. Written by hand in the same change as the contract; `tools/checks/changelog`
fails a change to `api/openapi.yaml` without an entry here.

Entry template:

```
## YYYY-MM-DD · AI-NNN · <capability or platform>
**Kind:** ADD | CHANGE | DEPRECATE | REMOVE | FIX
**What:** <operationId(s) / error code(s) / header(s) / setting(s)>
**Backend must:** <action or "nothing">
**Sunset:** <date, for DEPRECATE>
```

## 2026-09-25 · AI-016 · the job model (`ADR-007`, implemented) — `documents.ingest_job`, `jobs.get`
**Kind:** ADD (`documents.ingest_job`, `jobs.get`, `ai.job.not_found`; `JOB_TIMEOUT_SECONDS`, `WORKER_CONCURRENCY`, `WORKER_CONCURRENCY_PER_ORGANIZATION`); CHANGE, narrowing (`documents.ingest` refuses a document above 256 KiB of decoded bytes with `413 ai.input.too_large`, detail `use_the_job_operation` — below the line nothing moves)
**What:** `POST /v1/documents/ingest:jobs` (`documents.ingest_job`) takes the same `IngestRequest`, runs the door synchronously (switch, version, tenant cap — a refused input fails fast with the usual codes), stores the request as a job **from the verified path only** (the envelope verbatim, the payload bytes, their hash) and returns `202` with `Location: /v1/jobs/{id}`, `Retry-After: 2` and `JobAccepted {job_id, state, capability, retry_after_ms, request_id}`. The envelope of a job submission **must carry `job_exp`** (the window the job may start in; `401 auth.origin.invalid` without it — the reason `no_job_window` is in the service's security log). The same body from the same organisation is the same job (`INV-028`). `GET /v1/jobs/{id}?organization_id=<uuid>` (`jobs.get`; the envelope's `cap` is `jobs`, its `org` the query's) returns `JobStatus {job_id, capability, state: queued | running | succeeded | failed | expired | quarantined, attempts, created_at, started_at?, finished_at?, retry_after_ms?, result?, error?, request_id}` — `Retry-After` until the state is final; `result` is the capability's whole response (`IngestResponse`) on `succeeded`; `error` the error body on `failed`; `expired` and `quarantined` carry no detail of why. Any other organisation's job and an unknown id are `404 ai.job.not_found`. The worker verifies the stored envelope again before running (signature under `kid`, `org`, `cap`, the hash of the payload bytes it is about to run, `job_exp`), runs under `JOB_TIMEOUT_SECONDS`, bounded to `WORKER_CONCURRENCY_PER_ORGANIZATION` at once per organisation; results expire after `JOB_RESULT_TTL_SECONDS` and the retention command purges them.
**Backend must:** submit long ingests (documents above 256 KiB decoded) through `documents.ingest_job` with `job_exp` in the envelope — the capability's budget window from `ARCH-008 §1` (120 s per document is the floor; an hour is a safe ceiling) — signed at submit time; poll `GET /v1/jobs/{id}` from its own worker with the `Retry-After` it receives, signing each poll afresh with `cap: "jobs"` and `org` as the query parameter; treat `succeeded` (read `result`), `failed` (read `error`), `expired` and `quarantined` as final — `expired` means resubmit with a fresh window, `quarantined` means the row failed its proof and is the service's security event: do not resubmit blindly, look at what wrote it; treat a missing terminal state after `JOB_RESULT_TTL_SECONDS` as `ai.job.expired` and resubmit; never expect a callback.
**Compatibility:** additive but for the size line on `documents.ingest`, which the backend's client may already exceed for large files — the `413` names the operation to use.

## 2026-09-24 · AI-015 · platform — the proof of origin
**Kind:** CHANGE (the authentication scheme of every operation — breaking for the only caller, by the lead's decision `D-035`; the static bearer is removed, not kept as a fallback); ADD (`auth.origin.invalid`, `auth.origin.unverifiable`); REMOVE (`auth.token.invalid`, `SERVICE_TOKENS`); ADD (`AUTH_PUBLIC_KEYS`, `AUTH_CLOCK_SKEW_SECONDS`, `AUTH_MAX_TTL_SECONDS`)
**What:** `Authorization: Catalyst-Envelope <claims>.<signature>` on every operation but the health routes. `claims` is the unpadded base64url of a JSON object `{iss: "backend", aud: "catalyst-ai", org: <organisation uuid>, cap: <capability name as the document's x-capability>, sub: <the acting principal's opaque id>, iat, exp (≤ iat + 60), jti: <nonce, unique per request>, kid: <key id>, bh: <hex SHA-256 of the request body bytes exactly as sent>, job_exp?: <the capability's budget window, for job operations>}`; `signature` is the unpadded base64url of the 64-byte Ed25519 signature over the ASCII bytes of the `claims` segment, by the private key `kid` names. The service verifies signature, issuer, audience, window (clock skew `AUTH_CLOCK_SKEW_SECONDS`), the nonce once, the body hash, and that `org` equals the body's `organization_id` and `cap` equals the operation's capability. Refused: `401 auth.origin.invalid` with no detail (the reason is a security event on the service's side); `503 auth.origin.unverifiable` with `Retry-After` when the replay store cannot answer. The document declares the scheme as `CatalystEnvelope`.
**Backend must:** generate one Ed25519 key pair per environment (`crypto/ed25519`, the standard library); keep the private key in its own runtime configuration only (`CATALYST_AI_SIGNING_KEY`, RESTRICTED) and hand the public key to the service's configuration as `kid:base64url` (`AUTH_PUBLIC_KEYS`); sign every request at send time with `bh` over the exact bytes it sends, a fresh `jti`, `iat` now and `exp` ≤ 60 s later; for a job operation add `job_exp` (the capability's window) so a legitimately queued job is not refused by the request window; treat `401` as a signing defect on its side (never retry the same envelope — it is replayed), `503 auth.origin.unverifiable` as retryable after `Retry-After`; rotate by adding the new public key to the service first, switching `kid`, and removing the old key after the longest job window (`docs/06-runbooks/key-rotation.md`).
**Also:** the error catalog (`ErrorCode`) is declared `x-extensible-enum` in the document — it grows with every capability and a new code is additive, never breaking; a client treats an unknown code by its HTTP status and its family prefix (`ai.provider.*` retryable as before).
**Compatibility:** the static bearer is gone the moment this lands; the two sides deploy together (the backend's signing half is its own change against this entry). Nothing else in any operation moved.
