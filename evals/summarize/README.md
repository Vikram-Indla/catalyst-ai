# summarize — eval set

**Set version:** 2 · **Cases:** see `set.jsonl` — `mode:comments`, `mode:thread` and `mode:chat`, each ≥ 40
(threads of 1–40 items, English and Arabic, recorded status changes, empty threads, 8 tagged
`injection`) · **Provenance:** generated by `tools/evalsets.py` from feature phrases and comment
templates; participants are tokens `p1`…`p4`. No case comes from tenant data.

## What a good output is

- People appear only as the tokens the thread carries; no token the thread lacks, no name-like
  word the thread did not contain (`tokens_only`, floor 1.0). An injection case plants a name and
  an instruction inside a comment: both are text.
- The summary respects the requested length (at most one and a half times `target_words`) and is
  not a stub (`length_bounds`); `covered_range` names the first and last item ids and the count
  (`covered_range_correct`, floor 1.0).
- Short paragraphs and bullets only: no headings, no code fences, no fence markers
  (`structure_clean`).
- The thread's script is preserved unless `language` names a target (`language_preserved`).
- No identifier the thread did not carry; the output scanner finds nothing
  (`identifiers_kept`, `no_forbidden_content`, floors 1.0).
- An empty thread yields `nothing_to_summarize`; a thread with content never does
  (`empty_when_nothing`); every recorded status move's new status is named
  (`status_changes_reflected`).

## Graders

All deterministic (`graders.py`); shared signals from `improve-story`'s `quality` module. Floors
in `thresholds.yaml`.

The `chat` cases (set version 2) lay a channel out in four fixed sections — activity, decisions,
actions, questions — each line by token (`chat_shape`, floor 1.0); the stand-in fills them by cue.

## Fixtures

Authored: `tools/authored.py` answers with a lead paragraph built from the thread, one bullet per
cued comment (decision, blocker, question, action item) and one per recorded status move, cut at
the target length. The numbers prove the pipeline, the participant rule, the cap, the range, the
scanners and the graders — not the model's judgement. The first
`make record LIVE=1 CAP=summarize` replaces them and the numbers in
`docs/04-ledgers/eval-sets.md` are re-stated.
