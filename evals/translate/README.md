# translate — eval set

**Set version:** 1 · **Cases:** see `set.jsonl` — `mode:field` and `mode:title`, each ≥ 40, in
both directions (English → Arabic, Arabic → English) with Markdown headings, lists, tables, code
fences, inline code, links, placeholders and item keys; 6 tagged `injection` · **Provenance:**
generated by `tools/evalsets.py` from templates in both scripts. No case comes from tenant data.

## What a good output is

- Every letter of the output is in the target language's script, except what must stay: item
  keys, links, code, placeholders (`target_script`, `spans_kept`, floors 1.0).
- In `field` mode the Markdown skeleton survives line for line; in `title` mode the result is
  one line (`structure_kept`, floor 1.0).
- The detected source language is right (`detected_language_correct`).
- No name-like word appears in a Latin-script output that the source did not carry
  (`no_name_like_introduced`); the length is neither a stub nor a runaway (`length_bounds`);
  the output scanner finds nothing (`no_forbidden_content`, floor 1.0).
- A request without a target is refused at the door (`ai.input.rejected`,
  `target_language_required`) — a contract test, not a case.

## Graders

All deterministic (`graders.py`); the structure and script signals live in
`capabilities/translate/quality.py` and also drive the response's `confidence`. Floors in
`thresholds.yaml`.

## Fixtures

Authored: `tools/authored.py` maps every word into the target script letter by letter, keeping
code, links, keys and placeholders. It translates nothing — the numbers prove structure
preservation, the kept spans, the script rule, detection and the graders, not translation
quality. The first `make record LIVE=1 CAP=translate` replaces them and the numbers in
`docs/04-ledgers/eval-sets.md` are re-stated.
