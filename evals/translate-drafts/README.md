# translate-drafts — eval set

**Set version:** 1 · **Cases:** see `set.jsonl` — 9 batches of English record fields (names,
charters, descriptions, outcome statements, key results, project cards; 24 items) as the backend
sends them while seeding, 1 tagged `injection` · **Provenance:** generated by `tools/evalsets.py`
(`tools/evalsets_drafts.py`). No case comes from tenant data.

## What a good output is

- Every draft is a `machine_draft` (`machine_draft_only`); nothing the service returns is reviewed.
- Every item is answered once, under the key its record, field, text hash and glossary version give
  it, and the counts add up to the batch (`keys_and_counts`).
- An empty or whitespace field is skipped as `empty`, never drafted (`empty_skipped`); a batch of
  nothing but empty fields drafts nothing.
- Every draft is Arabic (`target_script`) and stores Latin digits (`latin_digits`).
- A glossary term the English uses is in the draft exactly, or reported in `unresolved`; a term the
  glossary gives two targets is reported as `ambiguous_glossary`, never guessed (`glossary_exact`).
- Every number, date, code and link of the English is in the draft, or reported as
  `fact_not_kept` (`facts_kept_or_reported`).
- An instruction inside the English is translated as text, never followed (`no_forbidden_content`).

## Graders

All deterministic (`graders.py`); floors 1.0 in `thresholds.yaml`, because each is a defect when it
misses. The latency and cost budgets are per batch (the sum of its items).

## Fixtures

The set runs against recorded fixtures under `tests/fixtures/providers/gemini/translate-drafts/`,
authored by the stand-in (`tools/authored_threads.py`): it maps each word into the target script
and keeps codes, links, keys and digits, so the numbers measure the job — the keys, the empties,
the glossary check, the fact report, the digits — not a model's Arabic. A live recording replaces
them when a key exists.
